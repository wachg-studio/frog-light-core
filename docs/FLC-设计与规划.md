# FLC（Frog Light Core）设计与规划

版本：v0.1 草案　日期：2026-10-21

## 1. 定位

FLC 是一款面向 Windows 优先、后续扩展到 macOS / Linux 的 Minecraft Java 版启动器。目标是在 PCL 的功能完整度之上，把四件事做到明显更好：**启动速度、运行性能、兼容性、界面体验**。

一句话原则：**快、稳、好看，而且默认就好用。** 功能可以多，但首屏永远只有一个“启动游戏”大按钮，其余按需出现。

### 对标 PCL 的差异点

PCL 的强项是功能全、中文生态好、下载源（BMCLAPI）接入成熟；弱项是 WPF + VB.NET 的单线程 UI 模型在大量实例/模组时容易卡顿，界面定制与动效能力有限，也只支持 Windows。FLC 要保留它的“开箱即用”，同时在架构上换掉这些天花板。

## 2. 技术选型

**推荐：Tauri 2 + Rust 核心 + Svelte（或 SolidJS）前端。**

- **Rust 核心**负责一切重活：版本解析、并行下载、校验、Java 管理、启动参数拼装、进程监控。无 GC、启动快、安装包小（预计 < 15 MB），并发模型天然适合下载与文件哈希。
- **前端用系统 WebView2**（Win11 自带）渲染 UI。CSS 的 `backdrop-filter`、GPU 合成动画、`View Transitions` 做玻璃和动效最省力，也不用自带 Chromium，比 Electron 内存低一个量级。
- **窗口材质**：用 Tauri 的 window-vibrancy 调用 Windows 11 原生 Mica / Acrylic，让窗口背景是真正的系统级玻璃，再叠加 CSS 层做卡片级的毛玻璃，两层配合效果比纯 CSS 好且更省 GPU。
- 跨平台代价几乎为零：同一份核心代码，macOS 用 vibrancy，Linux 降级为半透明。

备选方案及不选的理由：WinUI 3 / Avalonia 原生体验最好但动效与主题自由度和开发速度不如 Web 栈，且 Avalonia 的跨平台渲染在包体和启动上不占优；Electron 开发最快但体积与内存与“性能第一”的目标冲突。

## 3. 性能与启动速度（最高优先级）

“打开游戏的速度”拆成三段分别优化：点击到进程创建、JVM 启动到主菜单、以及启动器自身冷启动。

**启动器自身**：冷启动目标 < 400 ms 出现界面。做法是 Rust 侧只做最小初始化，其余（实例扫描、更新检查、新闻）全部异步；前端首屏用静态骨架，数据到了再填充；实例列表用本地索引缓存（SQLite 或单个 bincode 文件），不每次遍历磁盘。

**点击到进程创建**：目标 < 300 ms。关键是**把校验从“每次启动”挪到“安装/变更时”**。PCL 类启动器每次都会扫一遍 libraries 与 assets，我们改为：安装时记录每个文件的大小 + 修改时间 + 哈希到索引；启动时只比对 mtime 和 size（微秒级），仅在不一致时才重算哈希。拼装 classpath 与启动参数的结果也按实例缓存，配置未变直接复用。

**JVM 到主菜单**：这一段是游戏本身，但启动器能做的不少。
- 自动选择与版本匹配的 Java（1.16 以下 Java 8，1.17 用 16，1.18–1.20.4 用 17，1.20.5+ 用 21，以官方 `javaVersion` 字段为准），并内置下载 Temurin / Zulu，用户无需手动装 Java。
- 默认 JVM 参数采用经过验证的预设（G1GC 调优、`-Xshare:auto`，Java 13+ 支持时为实例生成 AppCDS 归档，二次启动明显更快），而不是让用户去抄参数。
- 内存按物理内存与模组数量自动分配，避免分配过大反而拖慢 GC。
- 可选“预热”：用户打开启动器时，后台预读该实例的 jar 与 assets 索引到系统缓存。

**下载性能**：全异步并发（tokio + reqwest），HTTP/2 连接复用，默认 16–32 路并发并按网络状况自适应；支持断点续传、分块下载；多源竞速（官方、BMCLAPI、其他镜像同时探测，选最快的并在失败时无缝切换）；assets 去重复用全局共享目录，多个实例不重复下载。

**UI 性能**：动画只用 `transform` 与 `opacity`（GPU 合成层）；长列表虚拟滚动；`backdrop-filter` 只用在少数大容器上，避免几十个小卡片各自模糊；检测到集成显卡或低电量时自动降级为纯色半透明。设有“性能模式”开关，并在设置里公开帧率与内存占用以便自检。

## 4. 兼容性

- **加载器**：原版、Forge、NeoForge、Fabric、Quilt、LiteLoader，以及 OptiFine（含与 Forge 共存）。安装流程一键完成，不要求用户理解依赖关系。
- **整合包**：CurseForge（manifest.json）、Modrinth（.mrpack）、以及 PCL / MultiMC / HMCL 的实例导入，导入后可无损还原。
- **版本范围**：从 rd-132211 老版本到最新快照，包括 Java 8 时代需要的 log4j 补丁参数、旧版 natives 解压、旧版 applet 启动方式的兼容分支。
- **账号**：微软登录（设备码流程，不需要内置浏览器）、离线账号、Authlib-Injector 第三方认证（LittleSkin 等）。令牌存放使用系统凭据库（Windows Credential Manager），不明文落盘。
- **平台**：Windows x64 / ARM64 优先，macOS（含 Apple Silicon 的原生 LWJGL 替换）与 Linux 随后。
- **启动失败诊断**：解析 crash report 与日志，给出人话原因（缺少依赖模组、Java 版本不对、显卡驱动问题、内存不足），并提供一键修复。这块是用户感知“兼容性好”最直接的地方，值得单独投入。
- **与 PCL 共存**：识别并可直接复用 `.minecraft` 目录，不强迫用户迁移。

## 5. 界面与交互设计

整体风格：**简约、留白多、层级少**。参考 Windows 11 Fluent 与 macOS 的质感，但保留自己的品牌色（青蛙荧光绿，作为唯一强调色）。

**布局**：左侧一条窄图标导航栏（主页、实例、下载、模组、设置），中央是内容区，没有多层嵌套菜单。主页就是当前实例的大封面、版本信息和一个醒目的“启动”按钮，账号头像在右上角。

**玻璃效果**：窗口底层为系统 Mica/Acrylic，可跟随壁纸取色；内容卡片使用轻度毛玻璃（模糊 20–30 px、1 px 半透明描边、细微内阴影高光）。深浅色跟随系统，并提供自定义背景图 / 实例封面取色（主色自动提取为强调色）。

**动效**：时长统一在 150–300 ms，用同一组缓动曲线（建议 `cubic-bezier(0.2, 0, 0, 1)`）；页面切换用共享元素过渡；启动按钮点击后原地变为进度环，进度由真实阶段驱动（校验→参数→启动→窗口出现），而不是假进度条；列表项进入用轻微错位淡入。尊重系统“减少动态效果”设置。

**易用性**：
- 首次运行向导不超过三步（选择/检测 `.minecraft`、登录、选择版本即可开玩）。
- 全局搜索（Ctrl+K）可直达实例、模组、设置项。
- 拖拽 .jar / .mrpack / .zip 到窗口即可安装模组或整合包。
- 每个实例独立配置，但默认继承全局，用户不改也能玩。
- 所有错误都用“发生了什么 + 怎么办”的两句话呈现，不抛堆栈。

## 6. 系统架构

```
┌────────────────────────── 前端 (Svelte + CSS) ──────────────────────────┐
│ 页面 / 状态 / 动效                                                       │
└───────────────▲──────────────────────────────────────────────────────────┘
                │ Tauri IPC（类型由 specta 自动生成 TS 绑定）
┌───────────────┴──────────────────────────────────────────────────────────┐
│ flc-app（Tauri 壳：窗口、托盘、系统材质）                                │
├──────────────────────────────────────────────────────────────────────────┤
│ flc-core：instance · launch · java · account · mods · diagnose           │
│ flc-net：下载调度 · 多源竞速 · 断点续传 · 镜像配置                      │
│ flc-store：索引缓存 · 配置 · 凭据                                        │
└──────────────────────────────────────────────────────────────────────────┘
```

Cargo workspace 拆成独立 crate，`flc-core` 不依赖任何 UI，因此可单独测试，也可以以后出命令行版或被其他前端复用。前后端通过强类型 IPC 约定，事件（下载进度、游戏日志）用流式推送而不是轮询。

## 7. 路线图

**M0 原型（约 2 周）**：搭好工程骨架；完成玻璃窗口与主页静态界面；验证 Mica + CSS 毛玻璃在 Win11 上的效果与 GPU 占用。这一步先做出来，是为了尽早确认视觉方向，也能提前暴露 WebView2 的性能问题。

**M1 能玩（约 4–6 周）**：版本清单解析、原版下载与安装、Java 自动管理、微软 / 离线登录、启动参数拼装、启动进度与日志。达成标准是任意原版 1.8–最新版能一键下载并进入游戏。

**M2 好用（约 4–6 周）**：Fabric / Forge / NeoForge / Quilt 安装；实例管理；多源下载竞速；校验索引缓存与启动提速；崩溃诊断第一版。达成标准是启动耗时在同机型下明显优于 PCL，需要有可复现的基准测试脚本。

**M3 完整（约 6–8 周）**：Modrinth / CurseForge 模组与整合包浏览、安装、更新；整合包导入导出；PCL/HMCL 实例导入；主题系统；Authlib-Injector。

**M4 打磨与发布**：低配降级策略、无障碍、自动更新（差分更新）、安装包签名、官网与文档、公开测试。

## 8. 质量与基准

没有数据的“性能更好”是空话，所以从 M1 起就建立基准：冷启动时间、点击到游戏窗口出现的时间（原版、Fabric + 50 模组、Forge + 150 模组三个场景）、下载整个 1.20.1 的耗时、空闲内存占用，每个版本都跑并记录曲线，退化即阻断发布。核心逻辑（版本 JSON 解析、规则匹配、参数拼装）用大量真实版本 JSON 做快照测试，这是兼容性的第一道防线。

## 9. 风险与待定事项

- **WebView2 依赖**：Win10 老机器可能没有，需要安装包带引导式安装（Tauri 支持）。
- **CurseForge API 密钥**：需向官方申请，授权条款会影响能否内置，需要提前沟通。
- **微软登录的 Client ID**：需要自己注册 Azure 应用并通过 Minecraft 服务审核，周期不确定，建议 M1 开始就申请。
- **开源与许可证**：是否开源、选哪种许可证，影响能否复用 HMCL / PrismLauncher 等项目的思路与代码（它们多为 GPL）。
- **品牌与素材**：Logo、青蛙形象、字体需要确定；避免使用 Mojang 的受限素材。
- **名称**：需确认“FLC / Frog Light Core”在商标与社区中无冲突。

## 10. 需要你拍板的决策

1. 技术栈是否接受 Tauri + Rust + Svelte，还是更倾向纯原生（WinUI / Avalonia）。
2. 首发平台是否只做 Windows，Mac / Linux 放到 M4 之后。
3. 是否开源，以及许可证。
4. 界面语言范围：只做简体中文，还是首发即支持中英。
