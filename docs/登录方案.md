# 正版登录方案

## 现在用的是什么

FLC 用的是微软的**设备码流程（device code）**：点“登录微软账号”后，启动器打开 `microsoft.com/link`，界面上显示一个 8 位代码，用户输入代码并授权，登录自动完成。这已经就是“点登录 → 打开网页 → 输入密钥”的形态，那个“密钥”就是设备码。

它需要两样东西：

1. 一个在 Azure 注册的应用 Client ID（账户类型选“仅个人 Microsoft 账户”，并允许公共客户端流）。
2. 这个应用通过 Minecraft 服务的审核，否则最后一步会返回 403。

Client ID 的获取步骤见 [构建与发布.md](构建与发布.md#微软正版登录的-client-id)。配置方式有两种：用户在 **设置 → 账号 → 微软登录 Client ID** 里填，或者构建时用环境变量 `FLC_MS_CLIENT_ID` 内置进安装包。

设备码方案不需要自建服务器，令牌直接回到启动器，是目前最省事也最稳的做法。

## PCL 那种“自己的网页 + 密钥”怎么做

如果要让登录网页挂在自己的域名下（比如 `wachg.xyz`），再由网页给出一个密钥交给启动器，需要做一层 **OAuth 中转（broker）**。分三步：

### 1. Azure 应用

在现有应用里加一个 Web 平台的重定向 URI，例如 `https://wachg.xyz/flc-auth/callback`，并生成一个客户端密码（client secret）。**密码只能放在服务器上，绝不能进启动器或仓库。**

### 2. 服务器

在 nginx 后面加一个小服务（Node/Python 都行，和现有游戏服务分开），提供两个端点：

- `GET /flc-auth/login`：生成随机的 `state` 和 PKCE 的 `code_verifier`，把用户 302 到微软的授权页：
  `https://login.microsoftonline.com/consumers/oauth2/v2.0/authorize?client_id=...&response_type=code&redirect_uri=...&scope=XboxLive.signin%20offline_access&state=...&code_challenge=...`
- `GET /flc-auth/callback`：校验 `state`，用 `code` + `client_secret` 在服务器端换令牌，再走 Xbox Live → XSTS → Minecraft 服务拿到玩家档案；然后签发一个**一次性、30–60 秒有效**的票据，存在内存或 Redis 里。
- `GET /flc-auth/token?ticket=...`：启动器轮询这个接口，拿到票据对应的 Minecraft 令牌后立刻作废票据。

### 3. 启动器

把“登录”按钮改成：`open_url(https://wachg.xyz/flc-auth/login)`，然后轮询 `/flc-auth/token`；拿到令牌后用现有的 DPAPI 加密保存逻辑写进 `accounts.bin`。也可以注册 `flc://` 自定义协议，让回调页直接唤起启动器，省掉轮询。

### 安全底线

- client secret 只在服务器；客户端拿到的只有短票据。
- `state` 必须校验，PKCE 必须用；票据一次性、短有效期；接口限流。
- 全链路 HTTPS；服务器日志不要把令牌打出来。
- 仍然需要通过 Minecraft 服务审核，否则最后一步照样 403。

这套方案要维护一个鉴权服务，复杂度和风险都明显高于设备码。除非确实需要自己的登录页面和品牌，否则建议继续用设备码。

## 多账号

账号数据已经按 Microsoft 账户的 UUID 分开存在 FLC 数据目录的 `accounts.bin` 里（DPAPI 加密），不是只存一个。界面上：

- 主页的账号面板在多账号时会出现账号下拉框，直接切换。
- 设置 → 账号 里列出所有账号，当前账号标“当前”，其他账号有“切换”按钮。
- 切换只改 `settings.accountId`，启动和皮肤会跟着换；退出登录只删对应那一个。

以后要加第三方账号类型（例如 Authlib-Injector 外置登录），可以在账号记录里加一个 `kind` 字段区分，现有列表和切换逻辑不用重写。

## 你要做的事

1. 注册 Azure 应用、允许公共客户端流、拿到 Client ID。
2. 把应用提交 Minecraft 服务审核。
3. 自用：在设置里填 Client ID；发布：在 GitHub 仓库 Secrets 里配置 `FLC_MS_CLIENT_ID`，然后重新打 tag 构建。
4. 如果一定要自己的登录网页：加重定向 URI 和 client secret，写上面两个服务器端点，再改启动器的登录按钮和轮询逻辑（这部分需要额外开发）。
