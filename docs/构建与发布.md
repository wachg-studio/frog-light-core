# 构建与发布

## 编译 exe

界面必须内置进 exe，否则它会去连开发服务器（`localhost:1420`），表现为“localhost 拒绝连接”。所以发布构建一定要带 `custom-protocol`：

```bash
npx vite build
cargo build --release -p flc-app --features tauri/custom-protocol
# 产物：target/release/flc-app.exe
```

`npx tauri build --no-bundle` 效果相同。改了界面后要先 `npx vite build`，再编译 exe。

## 打安装包

```bash
npx tauri build
# 安装包：target/release/bundle/nsis/FLC_<版本>_x64-setup.exe
# 免安装 exe：target/release/flc-app.exe
```

`tauri build` 会自动构建界面并内置进 exe，再用 NSIS 打出安装包（第一次会从 GitHub 下载 NSIS，需要联网）。
安装向导是简体中文，装到当前用户目录（不需要管理员权限），配置在 `src-tauri/tauri.conf.json` 的 `bundle.windows.nsis`；
向导的侧边图和页眉图在 `src-tauri/installer/`（BMP 格式，尺寸分别是 164×314 和 150×57）。

安装包目前没有代码签名，用户首次运行时 Windows SmartScreen 可能提示“未知发布者”。要消除这个提示需要购买代码签名证书，并在 `tauri.conf.json` 里配置 `bundle.windows.certificateThumbprint`。

## 微软正版登录的 Client ID

正版登录用设备码流程，需要一个应用 Client ID。拿到的步骤：

1. 在 Azure 门户（portal.azure.com）→ 应用注册 → 新注册。受支持的账户类型选“仅个人 Microsoft 账户”。
2. 身份验证 → 允许公共客户端流 → 是。
3. 复制“应用程序(客户端) ID”。
4. 新注册的应用需要先通过 Minecraft 服务的审核，否则登录最后一步会返回 403（界面会提示“Client ID 还没有通过 Minecraft 的审核”）。审核入口见微软给 Minecraft 登录接入方的说明（搜索 “Minecraft Java Edition app registration review”）。

拿到之后有两种用法：

- 开发 / 自用：在 FLC 的 设置 → 账号 → “微软登录 Client ID” 里填。
- 发布版：构建时设置环境变量，ID 会内置进 exe，用户不用填：

```bash
FLC_MS_CLIENT_ID=你的ID cargo build --release -p flc-app --features tauri/custom-protocol
```

登录令牌保存在 FLC 数据目录的 `accounts.bin`，在 Windows 上用 DPAPI 加密（只有当前 Windows 用户能解开）。

## 界面语言

界面文字以简体中文原文为键，其他语言在 `ui/src/locales/<代码>.js`。新增或修改了界面文字后：

1. 把新的中文原文加进根目录的 `keys.json`；
2. 给每个语言文件补上翻译；
3. 逐个运行 `node tools/check-locale.mjs <代码>`，直到都输出 OK（它会检查键是否齐全、`{占位符}` 是否保留）。

后端（Rust）返回的错误信息目前只有中文，不会随界面语言切换。

## 在 GitHub 上自动发布

仓库里带了两个工作流：

- `.github/workflows/ci.yml`：每次推送和 PR 都会构建界面、跑 Rust 测试、检查 15 个语言文件。
- `.github/workflows/release.yml`：推送形如 `v0.1.0` 的 tag 时，在 Windows 上构建发布版（已带 `custom-protocol`），并把
  `FLC-v0.1.0-windows-x64.exe` 和校验文件发布到 Releases。

发布新版本：

```bash
# 先把 package.json、src-tauri/tauri.conf.json、各 Cargo.toml 里的版本号改好
git tag v0.1.0
git push origin v0.1.0
```

想让发布版内置微软登录的 Client ID，在仓库的 Settings → Secrets and variables → Actions 里新建 `FLC_MS_CLIENT_ID`。不配置也能构建，只是用户要自己在设置里填。
